## Overall Impression

The phone layout is a real success: it keeps the ledger and stays calm at 300px. Sync works and is honest in its words, but it reads as a first draft: its setup path has a dead end, its one high-stakes decision (the conflict) is made blind and cannot be undone, and its controls do not look like the rest of Settings. The single biggest opportunity is making the conflict choice safe and informed: it is the only place this app can destroy a plan.

## What's Working

- **Stacked rows keep the ledger.** Line 1 is grip, number, title (wrapping with `overflow-wrap: anywhere`) and actions; line 2 chips, status and hours; line 3 the date range. Columns that narrow desktop windows drop stay dropped, and no width from 300 to 899px scrolls sideways.
- **Consequence-first copy at the risky moments.** The conflict text and the delete warning say exactly what happens to each device, focus lands on the safe choice ("Decide later", "Cancel"), Escape works and focus returns to the opener.
- **Careful key handling.** The key is masked by default, Copy falls back to showing it when the clipboard is unavailable, and the hint says plainly that anyone with it can read and change the plan. The Log hours dialog on a phone (focused hours field, decimal keypad, full-width Add) is the best phone moment in the app.

## Priority Issues

**[P1] The Settings button has no accessible name below 900px**
- Why it matters: app.css:2828 hides `.topbar-actions .label` with `display: none`; Export and Import keep a `title`, the theme radios an `aria-label`, but the Settings button (TopBar.tsx:59) has neither, so a screen reader announces an unnamed button and Sync becomes unreachable.
- Fix: give the button `aria-label`/`title` from `t.settings.open`, or hide the four labels with a visually-hidden class instead of `display: none`.
- Suggested command: /impeccable harden

**[P1] Sync setup has a dead end and a misleading error**
- Why it matters: the invite code is asked for only after a failure, as a red error, and that state offers only "Try again" while the generated key is already saved, so there is no way back. With "Use an existing key", a mistyped key that is not on the server goes down the new-key path (sync.ts:319) and is reported as "This server asks for an invite code", when the real problem is the typo. Since the invite code went live on 2026-11-11, every friend's first sync goes through this path.
- Fix: an optional "Invite code" field beside "Turn on sync" from the start; a Cancel in the invite state that calls `disable()`; on connect, when nothing is stored under the key, say so ("No plan is stored under this key. Check it, or turn on sync to start a new one.") instead of trying to create it.
- Suggested command: /impeccable onboard, then /impeccable clarify

**[P1] The conflict choice is blind and irreversible**
- Why it matters: the dialog shows only the server's update time (slashed format), nothing about this device's copy, and puts the primary style on "Keep this device's plan" even when the server's copy is the newer one. Either choice overwrites a whole plan, and nothing is snapshotted right before it (`pull` calls `replaceAll`). "Since they last agreed" is untrue on a first connect with local data. No `aria-describedby`, so the consequence text may not be read out.
- Fix: two equal summaries ("This device: 27 planned, 10 finished, changed dd.mm.yyyy hh:mm" / "Server: …"); no primary bias, or bias toward the newer side; write a backup of the losing side before overwriting (the web build already keeps automatic backups in IndexedDB); stacked full-width buttons on a phone; `aria-describedby` on the text.
- Suggested command: /impeccable clarify, then /impeccable harden

**[P2] Narrow widths: phone touch targets under 44px, and a sideways scroll at 1001–1230px**
- Why it matters: on phones every target is under 44×44: row actions 28×28 with Start beside Edit (a mis-tap starts a game), top bar 30×30, theme 28×24, drag grip 22×24, "Rate" 27×19, Show key/Copy and both banner primaries 24px tall. Separately, between 1001 and ~1230px the plan table outgrows its wrapper and the whole page scrolls sideways, cutting off Note and the actions.
- Fix: under 899px with `(pointer: coarse)`, a 40–44px minimum on `.button` and `.button-icon-sm` (negative margins keep rows compact); full-size buttons in banners, actions dropping under the text below ~400px. For 1001–1230px, give `.table-wrap` `overflow-x: auto` or drop Note one breakpoint earlier.
- Suggested command: /impeccable adapt

**[P2] The Sync group looks unfinished**
- Why it matters: the inputs render with browser chrome (no `type`, so a 2px inset border, square corners, 26px tall, grey in dark) and have no visible labels; the status line, the most important line in the group, is the quietest (14px muted, not live); offline is styled as an error; times are slashed and absolute; "Delete server copy" looks like plain text; the turn-off hint wraps under the delete button on a phone and reads as describing it; the group never folds.
- Fix: `type="text"` and field labels; a status word with a dot (Finish Green synced, Caution Amber waiting, Drop Red failed) in an `aria-live="polite"` region with relative time and dd.mm.yyyy; danger-ghost for delete with its hint directly under turn-off; fold to "Synced 5 min ago · Show key · Change" once set up; a recovery line for too-large.
- Suggested command: /impeccable polish (with /impeccable clarify for the copy)

## Persona Red Flags

**Casey (phone, one thumb):** Start and Edit sit side by side at 28px on every row; Settings is in the far top-right corner; "Reload" and "Choose which to keep" are 24px tall; Add game focuses the IGDB search even with no credentials, so the keyboard covers the form; 27 games make ~2,900px of 3-line rows; the Now playing progress bar shrinks to ~95px at 375 (≈20px at 300); at 300px the app name truncates to "Game Ba…" while Export, Import and three theme icons keep their space.

**Sam (keyboard / screen reader):** the Settings button is unnamed; "Use an existing key", "Cancel" and "Connect" unmount the focused button so focus drops to `<body>` (`data-autofocus` on the key input only works inside Modal); sync status changes are silent and the banners mount with `role="status"` already filled, so announcements are unreliable; the conflict dialog has no `aria-describedby`; key and invite inputs rely on aria-label/placeholder; at ≤899px `display: block/flex` on table, tr and td drops table semantics, so "–" and "Rate" lose their column context.

**The friend (gets the URL and an invite code, sets up a phone and a PC):** the first sync action produces a red error; a mistyped key yields an invite-code message with no way out; there are no setup steps; the App group says "never on a server" right under Sync; if the phone already has games, the first connect opens a conflict claiming the devices "last agreed"; 32 characters to type on a phone; "11/11/2026" is ambiguous to a US friend.

## Questions to Consider

- Should a conflict ever destroy data? A snapshot of the losing side, restorable for a week, would turn the scariest moment into a reversible one.
- Is the phone a planning surface or a logging surface? If it is "log 2 h, check what's next", should it open on Now playing with Log hours in the thumb zone and the 27-row list one tap away?
- Should the sync key travel as a link (…/#key=…) or a QR code from the PC instead of 32 typed characters, given the key already grants full access?
- Is the 899px block now a committed second mode with its own named rules (touch targets, row anatomy) in DESIGN.md, or a stopgap?
